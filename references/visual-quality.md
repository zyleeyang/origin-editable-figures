# 样式、预览与修正

用于新图、换数据套样式、批量图以及有视觉变化的修订。检查范围随任务缩放：小改动沿用当前文件和样式，只检查受影响部分及相邻对象；不为改一条线重新设计整组图。

## 先确定当前任务的样式

优先顺序：当前明确要求 → 用户最新手工修改文件中未要求改变的部分 → 已确认参考图/原生文件 → 本人既有偏好 → 本任务说明过的合理假设。冲突时依据当前意图处理；不能用模板覆盖用户修改。

把会影响输出的参数保存在本任务现有脚本/清单中，不重复维护一份会漂移的配置。新任务没有清单时，可复制 [样式记录示例](style-profile.example.json) 并替换为当前实测值；该文件只是记录格式，现有绘图脚本不会自动读取或应用它。对少量修改，用几行变更说明即可。至少确定本次相关项：

| 参数 | 如何确定 |
| --- | --- |
| 画布及最终使用尺寸 | 优先读原生文件；区分当前尺寸与以后缩放的尺寸，未知投稿宽度不编造 |
| 字体和字号 | 分开正文、刻度、面板编号、热图格内数字；记录其适用尺寸及来源 |
| 点和线 | 分开散点、数据曲线、轴线、误差线；表达数据的大小/线宽映射不能变成常数 |
| 配色和顺序 | 绑定实际分组名称、图例顺序和绘制顺序；新数据核查类别是否变了 |
| 轴及文字 | 记录范围、刻度、单位、变换、精度、长标签处理及文字归属 |
| 布局与保留区域 | 按实际绘图区对齐，记录当前要求预留的空间；不沿用其他项目的留白安排 |

截图只能给外观依据，不能精确确定字号、物理尺寸或原始数值；无法测得的参数明确为估计。已确认样式的数值可以复用，换数据时重新检查长标签、极值、组数及密度。样式修订不重算统计、重新排序或改变样本。

## 先校准，再展开

批量新图先选能覆盖风险的代表图：最密集/长标签、极值或特殊轴；不同图型分别选代表。只有一张图时直接检查该图。保存、重开并核对数据后，从实际 Origin 文件导出预览，打开查看；PPT 还需检查组装后的实际页面。

先解决代表图的共同问题，再展开同模板批量生成。已确认、未变的模板不重新设计；只重新检查当前变化带来的风险。校准由模型自主执行，除非用户要求先确认，或缺少影响结果的必要信息，不增加审批步骤。

## 看图时具体检查什么

在最终使用尺寸下看可读性，再放大看密集区域。图像查看器的缩放不能代替已记录的物理字号。

| 范围 | 检查与修正方向 |
| --- | --- |
| 单图 | 点/线是否被遮挡或裁切；边界、图例、误差线和单位是否完整；标签是否互相压住 |
| 文字 | 最长名称、上下标、负号、小数位、旋转文字是否正确；先调整位置、间距、文本框或换行，再按任务允许程度改变尺寸，避免全图文字一起缩小 |
| 热图 | 行列对应、缺失值和零值区分、色标范围、格内数值是否可读；深浅底上的文字对比；不为美观改变数值 |
| ROC/曲线 | 坐标刻度、曲线顺序、端点、参照线、图中指标与原始数据是否一致；不平滑或移动曲线来改善外观 |
| 散点/误差图 | 图层顺序、遮挡、点线相对粗细、完整误差范围、椭圆及其含义；保留数据映射 |
| 整组图 | 绘图区而非白边是否对齐；同类图的字号/线宽是否一致；跨行标题、图例与相邻面板是否碰撞；保留区域是否满足当前要求 |

## 检查必须对应实际修正

发现问题时留下简短记录：**位置与问题 → 修改了什么 → 修改后的预览及复查结果**。例如“第一排ROC横轴标题靠近下一排标题 → 调整标题位置 → 重导整页确认间隔，检查两排曲线未变”。必要时保留修前/修后两份预览；不累计无意义的重复截图。

从当前文件修改，避免对已经手工编辑的项目重跑旧清单。只改相关参数和对象；发现数据/方法错误则单独处理，不能混在样式修订里静默改变。

每次影响外观的改动后，重导并查看受影响图及其所在组图区域。文件保存成功、代码无报错、JSON校验通过，均不能替代实际看图。最终核验后再改动文件，先前对该部分的结论即失效，应做相应复查。

原生文字改内容或字体后，位置可能随文本框变化。局部修订应记录原锚点/位置，改后复查，必要时恢复位置；不能只确认字号和字符串正确。

## 结束条件与证据边界

- 本次要求的样式与内容满足；代表图和最终交付页面已实际查看，没有未处理的裁切、遮挡、错误标签或影响读图的重叠。
- 对齐与字号等可测项目经过核对；不把所有文本框交叠都当错误，旋转文字、注释和嵌入页白边需结合实际渲染判断。
- 数据正确性、视觉质量、原生可编辑性分别验收。好看不证明数值正确，原生对象存在也不证明PPT编辑回写成功。
- 一次检查通过即可结束；有缺陷时修正后复查，不固定“三轮”“十二轮”等次数。连续修改没有改善时重新定位原因；若确实受工具/数据限制，报告具体未完成项，不反复盲改或宣称通过。
- 看不到原生导出图时可以保留已完成的结构/数值检查，明确“视觉检查未完成”；不得根据脚本或文件名填写已查看。未测试的编辑行为同样明确标记。
- 原生实例按会话管理要求关闭；视觉检查使用已经导出的文件，不因收尾查询重新启动 Origin。

记录放在现有核验文件或简短说明中即可。可用三个状态分别记录：`data`、`visual`、`editable` 为 `passed / failed / not_tested`，并附本次检查的文件/页面及已修问题；不要求每次新建复杂报告。所有适用项通过后才报告完整验收通过。

## 复用已确认样式的边界

可复用的是：读取原生参考参数、按图型先校准代表图、检查数字格式和长标签、查看整页后解决标题拥挤、最后核对原生编辑能力。面板数量、排列、物理尺寸、字号、配色和留白属于各任务的具体需求，不能直接作为新图默认值。用户需要PPT组图时，若环境中有 `origin-ppt-assembly`，再使用其文字分工、最终缩放和原生嵌入的专项流程。
